C1 授權方式、Client ID 與 Device Flow

需你 review：是。

App 使用 Device Flow；不要求使用者提供 client secret。 無 remote 時，App 路徑仍可探索可存取的儲存庫。 探索與授權帳號必須一致。 最終 App 授權必須確認只限選定儲存庫。

需確認：共享 Client ID 只作為新設定預設值。 修改共享預設不會停用既有專案。

C2 Host 安裝、金鑰、pass 初始化與 probe 清理

需你 review：是。

只支援固定的 Debian、Fedora、Arch 安裝方案。 其他平台或沒有 sudo 時，顯示手動安裝指引。 只有套件安裝可用 sudo。 GPG 與 pass 操作使用目前使用者。

已有 recipient 時沿用設定，不重新初始化。 新 store 在選金鑰後重查 recipient，避免蓋掉中途建立的設定。 GPG parser 排除停用與不可用的加密金鑰。 離線 primary 配有可用 secret encryption subkey 時仍可使用。

probe 清理使用獨立的 10 秒 context。 清理失敗時停止授權，顯示可手動移除的 entry。 runCommand 使用 15 秒期限與 100 毫秒 WaitDelay。 WaitDelay 限制輸出 pipe 等待，不保證終止所有孫程序。

需確認：已安裝套件、新金鑰與 pass init 不會自動回復。 GPG 自行處理 passphrase；dch 不接收 passphrase。

C3 PAT 隱藏輸入、驗證與綁定

需你 review：是。

無 remote 時，PAT 可手動輸入 owner/repo。 秘密輸入拒絕非終端 stdin。 正常返回、取消或錯誤時均還原終端狀態。 PAT 不含 Client ID、refresh token 或虛構到期時間。 PAT 每次交付前重驗帳號與儲存庫。

需確認：metadata API 無法證明 PAT 只限單一儲存庫。 公開儲存庫 metadata 可讀，不代表能 push。 到期、撤銷或組織未核准時，需要重新設定 PAT。 PAT 不會自動 refresh。

C4 背景 GUI pinentry 與純 SSH 回復方式

需你 review：是。

service unit 帶入可用的 GUI session 環境。 pass 環境移除過時 GPG_TTY，指定 --pinentry-mode ask。 整個請求的 120 秒涵蓋鎖定、pass 與 provider。 GitHub API 仍保留較短的 HTTP timeout。

這項互動策略已於需求階段確認，最終實機行為仍未驗證。 dch 不修改 agent config，也不儲存 passphrase。

C5 切換、回復、清理與舊資料相容

需你 review：是。

App 舊 schema 1 與既有 pass entry 繼續可用。 PAT 使用獨立 schema 與 entry 身分。 清理不刪除目前使用中的身分。 secret 回復失敗會記錄 recovery 狀態，要求重新授權。

更舊的 installation credential 路徑仍拒絕使用。 Plugin.rejectLegacy／Plugin.quarantineLegacy 保留隔離行為。 這項隔離不是本次新增的遷移要求。

需確認：憑證回復與 host bootstrap 是不同範圍。 啟用失敗的回復不會移除 C2 已完成的 host 變更。
